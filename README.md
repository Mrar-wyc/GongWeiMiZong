一个古风宫廷推理游戏。你是大理寺仵作**沈墨白**，贤妃死在凤仪殿，
皇帝只给你三个时辰和一句话：

> 「三日之内，给朕一个名字。」

勘验尸首、讯问宫人、调取文书，把线索记进记事簿；**最后当着皇帝的面写下那个名字**。
指认对了是铁证如山，指认错了没有回头路。

一桩案子牵出下一桩：**凤仪殿的贤妃 → 尚药局的典药 → 经卷阁的掌籍女史**。
三案十一幕，91 份可调阅的档案，20 个结局——从一盏苦杏仁油，写到一页景和五年的旧账。

**两个前端，同一份剧本**：终端版（`python main.py`）与网页版
（`web/gongwei-mizong.html`，一个文件、离线可玩、手机也能开）。

## 怎么拿到

```powershell
git clone https://github.com/Mrar-wyc/GongWeiMiZong.git
cd GongWeiMiZong
```

唯一的硬要求是 **Python 3.8+**，而且只有终端版需要它。网页版连 Python 都不用装：
`web/gongwei-mizong.html` 是已经打包好的单文件，clone 下来双击就能玩。

## 怎么跑（终端版）

**零第三方依赖**——只用 Python 标准库，不需要 `pip install` 任何东西，
也不需要 `curses`（Windows 上自带的那份常常是缺的，所以本项目的终端层是自己写的）。

```powershell
python main.py
```

需要 Python 3.8+ 和一个**能交互的终端**。参数：

| 参数 | 作用 |
| --- | --- |
| `--continue` | 直接读取存档继续（没有存档则从新案开始） |
| `--save PATH` | 指定存档路径（默认 `%USERPROFILE%\.gongwei\save.json`） |
| `--no-save` | 禁用存读档，纯净试玩 |
| `--no-color` | 关掉全部 ANSI 颜色（等价于环境变量 `NO_COLOR=1`） |
| `--help` | 查看全部参数与按键 |

`python -m gongwei` 与 `python main.py` 等价。

> **Windows 提示**：如果中文显示成乱码，先设一下编码再运行：
> ```powershell
> $env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
> [Console]::OutputEncoding=[System.Text.Encoding]::UTF8
> ```

## 怎么跑（网页版 / 手机）

网页版是**一个 HTML 文件**：剧本、引擎、界面全部内联，没有任何外部请求，
拷到手机上用浏览器打开就能玩（窄屏切成「卷宗 / 档目 / 记事 / 检索 / 案外」五页；
宽屏把五页摊在右栏，上面再加四张仪表卡：进度 / 人物心意 / 线索囊 / 随身之物）。
界面学的是原型插画版的形制：标题屏一枚朱砂印章、落花与楷体书名，每一幕开场先推一卷
「画卷」过场（幕次、幕名、题引），朗读区里说话人的名字点金，档号与线索是描金小签。
背景里的宫墙、药柜、书架、藻井全是**代码画的**：一层 CSS 渐变与形状，跟着场景的地点与
时辰换色调，零图片、零外链——连那 19 枚图标也是内联 SVG 线条，所以它仍然是那一个文件。
第五页「案外」收的是卷外的东西：到过的幕、见过的结局、行囊里剩下的物证，以及动效开关
（系统开了「减少动态效果」也会自动关，`body[data-motion="off"]` 一处管到底）。

```powershell
python tools/build_web.py          # 重新打包（改了剧本就要跑一次）
python tools/build_web.py --check  # 只检查磁盘产物与当前剧本是否一致，不写盘
```

产物：

| 文件 | 说明 |
| --- | --- |
| `web/gongwei-mizong.html` | 单文件游戏（约 447 KB），双击即玩，离线可用 |
| `web/gongwei-pack.json` | 同一份剧本的纯数据（条件以 AST 形式导出，便于外部工具读） |

两端**共用同一份剧本、同一套判定**：Python 侧在导出时把每个条件编译成一棵可序列化的
AST，JS 侧解释执行；`tools/audit_web.py` 会把两端的**每一步存档与选项表逐字比对**
（27 条路线，含 5 条出错路径）——任何一边改了而另一边没跟上，门禁立刻红。

## 玩法

**两种操作方式并存**：点选动作（下面那排带编号的选项），或者**在 `›` 后面敲字**。

**按键**

| 键 | 作用 | 键 | 作用 |
| --- | --- | --- | --- |
| `↑` `↓` / `J` `K` | 选择动作、条目 | `Enter` | 执行指令 / 确认当前项 |
| `1`-`9` | 空行时直接选第 N 项 | `↑` `↓`（有输入时） | 翻指令历史 |
| `PgUp` `PgDn` / `U` `D` | 翻阅正文 | `Home` `End` | 卷宗：最新/最早；文档：开头/末尾 |
| `C` | 窄屏下切换「卷宗 / 记事簿」 | `R` | 从头重查一案 |
| `S` / `L` | 存档 / 读档 | `Esc` | 清空输入 / 关闭档案 / 回到标题 |
| `H` / `?` | 帮助 | `Q` | 退出 |

**指令**（在 `›` 后敲，回车执行；除注明外两端通用）

| 指令 | 作用 |
| --- | --- |
| `01-FY-XFE` | 敲档号直接调阅（也可写 `阅 01-FY-XFE`） |
| `档目` | 列出已收录的档案，按幕分组（终端可加页码 `档目 2` 翻页；网页版一页看全） |
| `搜 银针` | 在已读过的档案里找字 |
| `记 皇后在说谎` | 往记事簿上记一条 |
| `删 2` | 划掉记事簿第 2 条 |
| `帮助` | 指令说明（网页版另有 `关于`：版本与规模，终端版没有） |
| `存档` / `读档` / `重来` / `离开` | 存、读、重开一卷、回到标题 |
| 任何选项上的字 | 直接敲「移步侧殿」就等于点那一条 |

档案是这个游戏的主线道具：格目、尸格、值夜单、领用簿、对质录、旧案残卷……
**共 91 份，分十一幕（三桩案子）**，未收录的档会在档目里显示「还牵着 N 份」。
开局就收录两份（`01-DL-SMB` 勘验程式、`01-FY-XFE` 尸格），其余要靠查、问、
验一步步换回来。

**没进档目的档，只要档号拼得出来也能翻**——这是这一案的查法。走遍凤仪殿的现场，
你会看见 `01-FY-*` 那一串号子；顺出规律，就能自己往下敲。但**案子与案子之间有锁**：
案②、案③ 的档号在你走到那一案之前敲不开，屏幕上会说「这份档属于第 N 案，
你还没走到那一案」。锁只挡跨案，不挡同一案里的旧档——所以「翻旧账」永远是查案的
正路，而「翻到下一案去」不算。

**四条要记住的规矩**

- **核心线索（◆）**决定结局。全书 65 条（按「第一次拿得到的案子」算：案① 21 条、
  案② 25 条、案③ 19 条），取得越多，结案时的指认越站得住。
- **信任（人情）会随你的问话升降**。被得罪的人不会再对你说实话——有些话只在
  信任够高时才问得出来，而那些话往往正是钉死凶手的那一根钉子。
- **门禁是看得见的**。问不出口的话题会灰着显示、并告诉你缺什么（例如
  「需先取得『贵妃的汤』这条口供」），照着提示去别处取来证物再回来问。
- **案级剧情锁**：跨案的档案翻不开（见上），跨案的选项也各有各的门槛——
  想往下走，得先把眼前的案子结出个结果来。

## 代码结构

```
main.py                     入口（argparse + 启动 TUI）
gongwei/
  __init__.py               包入口（顺带把控制台编码兜成 UTF-8）
  console.py                Windows GBK 控制台的 UTF-8 兜底
  tui/
    terminal.py             零依赖终端引擎：CJK 双宽排版、ANSI、画布、键盘、行编辑器
    app.py                  界面：分栏布局、阅读区（卷宗/档案/档目/检索）、命令行、浮层
  game/
    models.py               数据模型（Item / Character / Choice / Topic / Scene / Dossier / EndingRule）
    conditions.py           条件小语言（clue: / flag: / trust: / evidence:core …），每个条件带 AST
    command.py              指令解析（档号、档目、检索、记事、存读档、帮助），两端同一套语义
    engine.py               规则引擎：选项、门禁、效果、档案调阅、指认、结局判定、存档读写
    save.py                 存档（原子写入、版本校验、容错）
  data/
    story.py                全部剧本与结局规则（场景、话题、结局）
    dossiers.py             91 份档案的正文与顺链
  web/
    pack.py                 剧本 → 内容包（条件编译成 AST）
    art.py                  图景台账：地点→色调、时辰→明暗、标签→字形（全是名字，没有图片）
  autoplay.py               脚本化通关原语（tools/ 与 tests/ 共用）
web/
  shell.html                单文件网页的骨架（占位符 __STYLE__ / __ART_SLOT__ / __PACK__ / __ART_TABLES__ / __GAME_JS__ / __UI_JS__）
  src/game.js               规则引擎的 JS 对等实现（含 AST 解释器与档案排版）
  src/ui.js                 网页界面：分页、阅读区、命令行、存读档、导出/导入
  src/style.css             宣纸暖色样式（无外部字体、无外部图片）
  src/static.css            图景的画法：宫墙/药柜/书架/藻井全是 CSS 渐变与形状（无图片、无外链）
  src/driver.js             node 下按脚本走路线（跨端比对用）
  gongwei-mizong.html       打包产物（单文件，可直接双击）
  gongwei-pack.json         打包产物（纯剧本数据）
tools/
  walk.py                   命令行按路线通关（开发时验证剧本）
  probe_story.py            场景图勘探
  audit_story.py            可达性体检：有没有「门槛永远够不着」的死锁
  audit_gates.py            线索/物证登记一致性
  audit_logic.py            游戏逻辑体检：后门、剧透面、刷分、死胡同、结局判定
  audit_web.py              跨端差分门禁：Python 引擎与 JS 引擎逐步比对
  build_web.py              单文件打包 + `--check`
```

**改剧本只需要动 `gongwei/data/story.py` 与 `gongwei/data/dossiers.py`**，
`engine.py` 不含任何剧情硬编码；网页端不用改，跑一次 `python tools/build_web.py` 即可。

> 要动手改这个仓库（人或 AI），先读 **[`AGENTS.md`](AGENTS.md)**：那里写了硬规则、
> 目录地图、内容约定、门禁基线与「踩过的坑」（同名函数静默顶掉、忘了打包、
> PowerShell 里怎么跑脚本……）。

想再加一幕（或一整案），顺序是固定的四步：

1. `gongwei/data/dossiers.py` 的 `ACT_TITLES` 加幕标题，再写一个 `_ACT12 = [D(...), …]`
   并接进文件末尾的 `DOSSIERS`（档号第三段决定它归哪一幕）；
2. `gongwei/data/story.py` 里写场景、选项与话题（用 `acting()` / `E()` / `Choice()`），
   新场景的 `act=` 填新的幕号；
3. 若新幕属于**新的一案**，只在 `gongwei/data/story.py` 的 `CASE_ACTS` 里加一行
   （例如 `4: (12, 13, 14)`）——`Content.act_case`、网页内容包、两端剧情锁与提示语
   全从这一处派生，不需要改引擎、也不需要改 JS；
4. 结局用 `_ending()` / `_rule()` / `_mk()` 登记，然后跑上面那六道门禁。

## 开发

```powershell
# 全部测试（302 项，跨端与结构那几道闸也在里面）
python -m unittest discover -s tests -t .

# —— 六道门禁，改完剧本按顺序跑 ——
python tools/build_web.py --check   # 网页产物是不是当前剧本打的包
python tools/audit_gates.py         # 线索/物证是否都登记过、门禁引用是否有据
python tools/audit_web.py           # 跨端差分：27 条路线，两端逐步比对存档与选项表
python tools/audit_story.py 30000   # 可达性：撒网 + 20 条结局路线（参数是预算步数）
python tools/audit_logic.py         # 逻辑体检：后门、剧透面、刷分、死胡同、结局判定

# 跨端差分也支持自定义路线：`#档号` 是调阅档案，其余是选项文字（可用前缀）
python tools/audit_web.py --steps "#01-FY-XFE" "细查门窗" "查看茶与香炉" "翻检塌上枕下"

# 按脚本走一遍真结局，逐行打印每步的场景/线索/核心数
python tools/walk.py

# 场景图勘探（看某一段的场景/话题/出口）
python tools/probe_story.py
```

这六道门禁 + 302 项测试每次 push / PR 都会在 GitHub Actions 上自动跑一遍
（`.github/workflows/gates.yml`，两条腿：Windows + Python 3.13、Linux + Python 3.9），
标题下面那枚「门禁」徽章就是它的结果。

> 产物是**按字节**比的（`build_web.py --check` 认死 457416 / 353698），
> 所以 `.gitattributes` 把全仓锁成了 LF——换行符被 git 转过一次，门禁就会在
> 别的平台上误报，看着像剧本坏了，其实只是 git 动了手脚。

怎么读这些门禁的输出：`audit_story.py` 会打印 `场景 64/64`、`档案 91/91`、
`线索/物证 103/103（核心 65/65）`、`话题 44/44`、`结局 20/20`，并且**有缺口就退出码 1**
（它还会把 20 条结局路线各真走一遍，再从案②/案③ 的几个深处起独立撒四口深井——
只从开局撒网会陷在案① 的岔路里出不来）。
`audit_logic.py` 分九节：幕/案推进有没有没上锁的后门、开局能拼出哪些档（跨案的一律报错）、
选项 key 冲不冲突、兜底结局是不是「什么都没查出来」那一档、有没有死胡同（分三档：**硬死**
与**翻不动的软卡**——手上那些档翻开哪一份都不改变任何东西——才算问题；翻档能翻出新东西的
软卡是案① 开局的正常节奏，只报个数，加 `-v` 才列明细）、灰置的选项有没有写理由、问询退场回没回到本案同一幕的前厅、
有没有「可重复又给分数/信任」的刷分口子、每条结局路线判出来的是不是它自己那条。

测试覆盖的层次：终端排版（CJK 双宽、禁则、ANSI）、条件语言、规则引擎与存档
（含原子写、坏档/高版本容错）、档案调阅（敲档号屏幕上真的出现正文）、剧本完整性
与**脚本化通关回归**（走完真结局、20 个结局分支、多种终端尺寸的渲染快照），
以及几道**静态闸**——它们专抓「测试全绿但真机是坏的」这类事故：

- **重名定义**（`tests/test_structure.py`）：Python 里后写的同名函数会悄悄顶掉前一个。
  这个项目真的栽过一次：`app.py` 里有两个 `_draw_left()`，旧的那个把带阅档功能的新版
  盖掉了——引擎状态全对、屏幕全错，而当时的测试只看行数与宽度，于是一片全绿。
  现在扫 `main.py`、`gongwei/**/*.py`、`tools/*.py` 的重复定义。
- **界面接线**：`self.engine.X` / `self.state.X` / `self.content.X` 必须真的存在
  （抓过一次「`act_title_of` 长在 state 上却写成 engine」，一敲「档目」就崩）；
  `web/src/ui.js` 里 `game.xxx` 调的每个方法也要在 JS 引擎里存在（用 node 真跑一遍）。
- **JS 重名函数**：`web/src/game.js`、`ui.js` 里的 `function` 声明不得重复
  （抓过一次「整屏空白」）。
- **打包一致**：`web/gongwei-mizong.html` 必须等于当前剧本的打包结果（改了剧本忘了
  重新打包就红），且产物里不得出现任何 `http://` / `https://` 外链。

两份**交叉验证**：

- **读档保真**（`SaveResumeFidelityTest`）：不只比字段，而是比行为——真结局路线上
  **每一个切点**存档读档后，终局状态与「从没存过档」的那一局必须逐字段相同，
  读档后立刻能看见的选项（含门禁提示）也必须与存档那一刻一样。其中一条专测
  「停在判决过渡场景时存档，读回来要自己补上结局」。
- **屏幕清点**（`ScreenInventorySnapshotTest`）：把 34 种屏幕状态（14 种界面状态 + 20 个
  结局屏：标题屏、帮助浮层、确认框、窄屏切栏、门禁提示、判决过渡……）× 5 种终端尺寸
  = 170 种组合逐个验行数与可见宽度，并在大尺寸下断言关键字样真的在——防「不崩但是空白」。

`tools/audit_story.py` 是最有用的一个工具——它靠「两遍深度优先（顺序 + 逆序）+ 状态
指纹去重」穷举整张状态图，专门用来抓「某个门禁的门槛永远够不着」这类死锁。
开发过程中它真的抓到过两处：皇后线的 `hh_motive` 和贵妃线的 `gf_who`——
两者的门槛都设在了角色信任永远到不了的高度，导致整条支线（以及依赖它的真结局）不可达。
它还会报「从未解开过的门禁」：每个被挡过的选项至少要在某条路上亮过一次
（按「场景 + 选项」统计），外加**把 20 条结局路线各真走一遍**、从案②/案③ 的
几个深处起各撒一口深井——只从开局撒网会陷在案① 的岔路里出不来。

## 已知取舍

写在这里，免得读到的人以为是漏了：

- **评分只是面板上的一个数**。它能涨，但不进任何结局条件——结局只看核心线索、
  关键口供、旗标与指认对象。想要「高分结局」的话，改 `_rule()` 的判据即可。
- **自拼档号只影响「收录」**。敲出一个没进档目的档号，它能读、会进档目，
  但不额外给分、也不改结语（`Dossier` 的模块注释里那句「会改变评语」尚未实现）。
- **剧情锁只到案一级**。跨案敲不开（第一案里翻不到案③ 的问询录），
  同一案里的旧档则随便翻——那是这一案的查法，不是漏洞。
- **判决屏的正文不进屏幕，但会留一行「节拍」**。判决屏是瞬时中间态——进入即结算，
  它自己的标题与正文在终端、网页、`autoplay` 与读档四条路径上都来不及单独显示；
  正文随 `go_to()` 记进卷宗（结局屏左栏就读得到），标题则由引擎补记一行
  `【判决】…` 当节拍。想让它真正露脸，要么改成需要确认的过渡，要么把正文并进
  对应结局屏的开头。`verdicts` 只登记 11 个嫌疑人——冯保与萧衍各在两案里出现，
  一张表放不下两条，所以指认去哪儿由 `Engine.verdict_target()` 按**当前案号**
  从剧本的指认选项里推，推不到才退回那张表（`web/src/game.js` 同形）。
- **还剩一个预留字段没接线**：`Effect.hurt`（「心绪」）链路完整——引擎累加、存档、
  网页顶栏按非 0 显示——但剧本里 0 处产出，终端也没有那一格。
  14 个 flag（`case2_entered`、`zzz_confessed` 之类）只设不读，留着当路标；
  它们登记在 `tests/test_story.py` 的 `BREADCRUMB_FLAGS` 白名单里，新加一个没人读的会红。
- **第四幕是唯一没有场景的一幕**。「第四幕 · 采薇（旧案）」全靠敲档号读出来（两份档：
  `04-DL-SMB`、`04-YC-CW`），档目按幕分组时用的正是这条幕名——所以它不算孤儿，
  只是玩家永远走不进「第四幕」。`tests/test_story.py` 的 `ActTitleTest` 盯着两件事：
  幕名表里不许有谁都不用的幕，实际用到的幕号也必须有幕名（且从 1 起连续不跳号）。
- **`audit_logic.py` 第 5 节会打印一行「另有 N 处软卡」**：那是案① 开局的正常节奏
  （选项全灰、但翻档能翻出新东西，翻完就解），只有个数、加 `-v` 才列明细。
  真正算问题的是「翻不动的软卡」（翻哪一份档都不改变任何东西）——当前是 0 处。
- **真实浏览器仍靠手工**。`web/src/ui.js` 现在会被 `tests/test_webui.py` 拖着
  `tests/webui_harness.js` 在 node 里跑一遍——手写的最小 DOM（没有 jsdom，也不许引），
  走的是真动作：开屏、开新案、敲档号阅档、档目、检索、记事、帮助浮层、存档、
  读档面板、读回一份结案存档（那份存档由 Python 引擎走真结局写出来，顺带验了
  存档跨端读得回来），外加两条 JS 侧的断言（判决屏那一行「节拍」与跨案指认
  跟 Python 一致；命令行里 ↑↓ 翻指令历史、且帮助表上列出的每一条都真敲得通）；
  把 ui.js 弄坏或把「读档」指令摘掉，它都会红。但**布局、滚动、
  移动端视口**这些只有真浏览器说了算，仍是发布前手工过一遍，脚本不进仓库。
- **网页版的「好看」也有一部分是测试守着的**：`tests/test_web_tokens.py` 静态解析
  `web/src/style.css`（不跑浏览器），查设计令牌有没有定义、每一档字号有没有被用上、
  正文色对比度够不够（AA）、阅读区与选项区有没有偷偷加回内滚、`:focus-visible`
  与 `prefers-reduced-motion` 还在不在。想把内滚或浅金色当正文用，它会先红；
  改完界面还必须在真浏览器里重看一遍，重拍的三张复验图放在 `docs/ui/`（宽屏、窄屏、结案屏）。
- **存档各一个槽**：终端在 `%USERPROFILE%\.gongwei\save.json`，网页在 localStorage
  的 `gongwei_save`；网页版可以导出/导入 JSON 当作多槽用。

## 关于

本作的界面、人物与案件设定脱胎于一份单文件 HTML 原型
（`reference-gongwei-mizong.chatglm.html`，存档于本目录）。那份原型是一部**空壳**：
点选项只会弹一句对话气泡、把同一段正文覆盖一遍、让信任值动一下，
没有分支、没有章节、没有门禁、没有结局，`updateUI()` 里只有一行 `console.log`。

这个版本把它**真的做成了游戏**：完整的场景图、带门禁的话题、可升降的信任、
91 份可调阅的档案、65 条核心证据与 20 个结局，并且终端与网页两端共用同一套判定。

另有一份更近的原型——`宫闱迷踪 v1.1 插画版.html`（698,661 字节，77% 是 base64 插画）。
它的逐段拆解与借鉴清单在 [`docs/prototype-v1.1-review.md`](docs/prototype-v1.1-review.md)：
哪些做法值得偷（图景靠名字不靠图、说话人名牌、音效现吹、元进度收集页），
哪些明确不学（77% 的字节是插画、两处函数/键名静默重名、可无限重试的推演、5 秒阻塞过场）。
